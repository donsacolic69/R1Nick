## 1. Criteria (verbatim from the paper, unchanged)

**Table 2.1, mechanical filter (title, abstract, metadata). Exclude if:**
- F1 review, perspective, editorial, erratum
- F2 not metal LPBF: wire-arc AM, DED, binder jetting, EBM only, polymer powder bed, or a subtractive process
- F3 the studied process is a post-build treatment (HIP, heat treatment, peening, machining), not the LPBF build itself
- F4 the output is microstructure or individual phase content with no link to a quality outcome

**Q1 and Q2 (title and abstract).** "Q1 addresses the role of the model: primary, if a model linking a process or machine input
parameter to a quality-relevant outcome is the core contribution of the paper; secondary, if a model is present but is not the paper's
main focus; absent, if no model is present (Table 2.2). Q2 addresses the ground-truth basis of the model: empirical (X-ray computed
tomography (XCT), coordinate measuring machine (CMM) data, profilometry, mechanical testing, or an in-situ sensor signal used as a
training label), simulation-based only, or unstated. Unstated cases were carried to full text."

**Table 2.2, title/abstract decision**
| Q1 | Q2 | Decision | Full text |
|---|---|---|---|
| Primary | Empirical | Include | FT1 to FT3 required |
| Primary | Simulation-only | Include, flagged | FT1 to FT3 required |
| Primary | Unstated | Carried to full text | FT1 to FT3 required |
| Secondary | Any | Exclude | not reached |
| Absent, measurement paper | Any | Include, measurement side only | FT1 to FT3 required |
| Absent, not a measurement paper | Any | Exclude | not reached |

"Measurement paper" (criteria lock 18.08.2026): a measurement, metrology or segmentation-method paper. A paper that only measures
properties is not a measurement paper.

**Table 2.3, full text. A record must meet all three:**
- FT1 Model role confirmed as primary
- FT2 Ground truth confirmed as empirical
- FT3 A quantitative performance measure is reported (for example accuracy, R2, error, probability of detection, precision or recall), not a qualitative claim alone

**Standing rules SR1 to SR6 (supplement S2.1)**
- SR1 model input is a post-treatment state or measured material property, not a raw machine parameter: include
- SR2 designed variable is alloy chemistry or composition, not process settings: include only if the model jointly connects composition and process to a quality outcome
- SR3 model target is a process response (melt pool geometry, thermal field), not a quality outcome: exclude, unless the paper also links that response forward to a quality outcome
- SR4 feedstock or powder-bed state is characterized, upstream of the built part: include only if carried forward to a build-quality outcome in the same study
- SR5 model connects LPBF quality metrics to downstream application performance (corrosion, joint strength, machinability): include, if the LPBF process/quality link is explicit
- SR6 LPBF variant with an added step, non-structural material, or multi-process comparison: include if LPBF is a primary studied process

## 2. Clarifications A1 to A5 (readings of the wording above, decided by Nick 29.10.2026)
They do not add criteria; they fix how recurring borderline wording is read, so that both reviewers read it the same way.
- **A1. Experiment with no model.** Q1 absent and NOT a measurement-method paper (metrology, XCT or other measurement method, segmentation method, instrument or sensor evaluation) -> Exclude (Table 2.2, "Absent, not a measurement paper"). A measurement-method paper stays "Include, measurement side only".
- **A2. SR3/SR4 without forward link.** Target is a process response (melt pool geometry, thermal field, layer thickness, parameter drift) or a powder/feedstock state, and the title/abstract does NOT state a link forward to a quality outcome of the built part -> Exclude. If the link is stated, decide by the other checks.
- **A3. Design variable as input.** Model input is a design variable (lattice or unit-cell geometry, topology, wall thickness) and not a process or machine parameter, a measured material property or a measured defect geometry -> Exclude. If a process parameter is also an input, A3 does not apply.
- **A4. Measured defect geometry as input.** Input is a measured defect geometry or descriptor (for example XCT-derived pore size or position, surface feature size) and the output is a quality or performance outcome -> Include (SR1).
- **A5. In-situ signal or image as input.** Include only if all four are yes: (1) at least one input is a process parameter, machine setting, or a sensor signal or image recorded DURING the build (melt pool camera, photodiode, pyrometer, acoustic emission during printing, optical tomography, layerwise powder-bed or part image, thermal camera); XCT, ultrasound after the build, SEM, microscopy, photos of the finished part, acoustic emission during tensile tests are NOT during the build; (2) the output is a quality characteristic or defect state of the part (porosity, density, lack of fusion, keyhole, balling, cracks, roughness, geometric deviation, a mechanical property) or a class labelled by one; process state only is not (A2); (3) that model is the core contribution, not a controller, framework or dataset built around it; (4) the process is metal LPBF. If one answer cannot be read from the title and abstract, the record is Borderline with that question named.
- **A6 (struck 29.10.2026).** There is no rule "unsure always advances". At title/abstract only an unstated ground truth (Q2) is carried to full text, as the paper says. Other unresolved cases are decided by each reviewer (P3).

## 3. Procedure
- **P1. Order.** F1 to F4, then a standing rule if one is triggered, then A1 to A5 where they apply, then Q1/Q2 (title/abstract) or FT1 to FT3 (full text). The reason for exclusion is the first check that fails.
- **P2. Mechanical filter (stage 1). Joint pass (Nick, 30.10.2026; paper 2.3: "both reviewers applied it").** Both reviewers apply the filter together in one pass, with one decision per record agreed between them. A record is excluded only with a named F code and a verbatim quote. Low confidence, or no agreement on an F code, is not a reason to exclude: such a record passes to title/abstract.
- **P3. Title/abstract (stage 2).** Two independent reviewers. A record advances if either reviewer includes it (paper Section 2.4). Borderline records are decided by each reviewer with one line of reasoning (My_note); a one-line reading is about one record, not a new rule.
- **P4. Full text (stage 3). CHANGED from the paper (amendment, Osman to-do 2.2). No third reviewer (Nick, 30.10.2026).** Both reviewers assess FT1 to FT3 independently. Agreement is final. A disagreement goes to a consensus discussion between the two reviewers, with the outcome and one line of reasoning recorded. A record still without consensus is included, flagged "single-reviewer inclusion", and covered by the sensitivity analysis (main results recomputed without the flagged records, as in Section 2.4). Every excluded report records the first criterion not met (FT1, FT2 or FT3) with a verbatim quote and PDF page.
- **P5. Evidence.** Every Pass and every Fail carries a verbatim quote (title/abstract: from the record, max 30 words; full text: with PDF page). No quote, no Pass.
- **P6. AI reviewers (amended 30.10.2026, Nick; editors' permission relayed by Osman 28.10.2026; use of AI to be disclosed in the letter to the editor).** The two reviewer passes are performed by two independent AI sessions, R1 (Nick's) and R2 (Codrin's), each started fresh from the same written brief and the same frozen rules, each blind to the other's files, to the key files and to every earlier screening decision. Each session decides every record itself, including Borderline cases (one line of reasoning per decision, A6 struck), with code and verbatim quote. The model ID and start time of each session are logged. The two result sets are reconciled in the parent session under P3 (title/abstract: union) and P4 (full text: consensus); Nick and Codrin sign off the reconciled list and may overrule any AI decision, each overrule logged with a reason. Agreement statistics are reported for the two AI sessions and labelled as such.
- **P7. Traceability.** Decisions are entered in TRACE_2026-10-30.xlsx (Record_trace) and never overwritten; corrections are added as notes. Every step that changes data gets an entry in METHOD_LOG.md.
- **P8. Reuse of the 28.10 screening.** Not settled by this version. 824 of the new records were screened by R1 on 28.10 under RULES_FINAL v1 with A6 still in force. Whether those AI suggestions may be shown to R1 is decided by Nick when stage 2 is set up, and logged.
- **P9. Grading (M0 to M4, evidence tiers, Yes/Partial/No).** Out of scope for screening. Who grades, how, and the definition of Partial for each link are to be fixed before extraction (Osman to-do 2.4).
